## Rulings applied (READY)

1. **Slash command opens the panel only.** `/roadmap` is registered once with
   `context: "workspace"`. Installed0.12 composer matching makes this command available in
   both workspace draft and existing-agent composers; per-plugin names must be unique across
   contexts. `onSubmit: (ctx) => ctx.openPanel("roadmap")`. `args` is ignored. It makes no
   RPC, no write, no approval and no permission change. Host evidence and the superseded
   two-registration assumption are recorded in the 2026-10-22 clarification below.
2. **Renderer is an answering surface using existing RPCs.**
   - Timeline row kind `decision-question`, version 1, data schema
     `{ projectId, sessionId, questionId }` (strict).
   - The `Component` fetches `session.get` for the row's `projectId` and renders the question
     as the panel's question card does: options, recommendation, free text, stale and inactive
     states. It answers through `QuestionAnswer` with `expectedRevision` from that fetch,
     `source: "ui"`.
   - Row data carries **no** question text or answer, so the row can never show stale
     content. The current state always comes from the store.
   - Theme colours and `layout.compact` are honoured; no DOM.
   - If `projectId` does not resolve (`unknown_project`) or the question no longer exists, it
     renders a muted "Decision no longer available" line.
3. **No identity inference.** Nothing derives an agent id from a cwd, grant, provider or
   timing. Rows are appended only to an agent id delivered **by the host** (the Agent-timeline rows section, step 1).

## Agent-timeline rows (plan Task 5.1): evidence and design

**Verified facts** (E5 reports; installed custom 0.12.0 source):
- **Plugin sessions are owner-permission sessions.**
  - `attachPluginSocket` → `OWNER_SESSION_ADMISSION` (`server/websocket-server.js:264-267,594-603`).
  - Subscribe (`agent.timeline.set_subscription`, `operation-permissions.js:20`), refetch
    (`:76`) and append (`:16`) are all **allowed**.
  - There is **no workspace or agent ownership scoping** in subscribe or append
    (`session.js:1823-1832,5965-5976`).
  - Append forces `pluginId` from the authenticated connection.
- **Self-scoping is mandatory.** The plugin observes and appends only to agent ids delivered by
  host events (`agent.turn_started`, `agent.turn_ended`: `plugins/lifecycle/index.js:53-79`),
  and only after re-resolving that agent's `cwd` to an opted-in project. That means Stage 2
  `projectForCwd`, then `resolveProject`, then store `ok` and not `disabled`.
- **In-turn delivery is supported:** `timeline.subscribe` delivers live items, including
  `tool_call` `running → completed` transitions (`client/dist/index.d.ts:246-261`).
  `turn_started` gives the agent id. "Only a turn-end route" is false.
- **`turn_ended.timeline` is the agent's whole folded history** (`agent-manager.js:3670`,
  `agent-timeline-store.js:33-38`). Tool calls are folded by `callId`, and same-identity plugin
  rows are folded to the latest. **Items carry no `turnId` or `seq`**, so per-turn filtering is
  impossible and timestamps are not identity.
- **Same-id upsert:** plugin row identity is `${pluginId}/${item.id}`, and a later append with
  the same identity folds in place (`protocol/timeline-identity.js`,
  `agent/timeline-projection.js:95-134`).
- **Durability:** appended rows go to a durable queue and are restored on reload
  (`agent-manager.js:675-677,1652-1666,3503-3509`). "All rows lost on restart" is false.
  Flush and kill semantics remain unverified (rows still queued at a hard kill may be lost).
- **Tool names** (exact server-bound forms; no suffix or bare matching):
  - Claude: `mcp__decision-roadmap__<tool>`, with `detail.input`/`output` present
    (`claude/agent.js:573-590`, `options.js:91`).
  - Codex: `decision-roadmap.<tool>`, with `result → detail.output`
    (`codex/tool-call-mapper.js:461-470,704-721`). Codex's bare-name fallback (empty server)
    is **not** authoritative.
  - OpenCode and Pi pass provider-raw names. Their separator is **unknown (E6)**.

**Design (READY for Claude and Codex):**
1. **Observed set.**
   - On `on("agent.turn_started", { agent })`: re-resolve the project from `agent.cwd`. If the
     project is opted in and `agent.provider ∈ {claude, codex}` (OpenCode/Pi after E6), ensure
     **one** subscription for `agent.id`, keyed by agent id, with at most 32 live
     subscriptions.
   - When the cap is reached, no subscription is opened and that agent relies on the
     `turn_ended` catch-up. This is logged with the agent fingerprint only.
2. **Event handling** (subscription handler, and the `turn_ended` snapshot scan):
   - Accept only `tool_call` items with `status: "completed"` and `name` exactly in
     `TOOL_NAME_SET[provider]`:
     - `claude: { "mcp__decision-roadmap__roadmap_ask", "mcp__decision-roadmap__roadmap_answer", "mcp__decision-roadmap__roadmap_confirm" }`;
     - `codex: { "decision-roadmap.roadmap_ask", "decision-roadmap.roadmap_answer", "decision-roadmap.roadmap_confirm" }`.
   - Parse the stream payloads with the protocol `agent_stream` payload schema from
     `@getpaseo/protocol` (read its exact shape in the implementation turn). Only items that
     schema yields as `ToolCallTimelineItem` are considered.
3. **Candidate refs, never authority.** From `detail` (`type: "unknown"`, `input`, `output`):
   - `roadmap_answer`/`roadmap_confirm`: `{ sessionId, questionId }` from `input`.
   - `roadmap_ask`: `sessionId` from `input` and `questionIds` from `output`. The output is
     JSON text, either a string or a text content block; parse failure → skip.
   - Missing or malformed fields → skip, with no row.
   - **Installed 0.12.0 output clarification (2026-10-22):** retain the JSON-string and
     single text-block forms above, and cover the actual provider envelopes: Claude's
     `detail.output = { output: { revision, questionIds, visibilityChanged } }`, and Codex's
     `detail.output = { content: [{ type: "text", text: "<JSON payload>" }] }`.
     Claude `agent.js` handleToolResult/buildToolOutput parses the MCP JSON and its
     tool-call-detail-parser preserves the wrapper; Codex mapMcpToolCallItem preserves the
     MCP result envelope and its generic detail parser preserves that output. These are
     bounded data-shape adapters, not recursive object searches. Malformed/error envelopes
     are skipped. Source is the active fnm custom 0.12.0 install under
     `@getpaseo/server/dist/server/server/agent/providers/`; re-verify after upgrades.
     The exact three-name sets per provider remain unchanged. No bare, arbitrary-server,
     alternate-separator or suffix matching is permitted. Direct/structuredContent payloads
     and arbitrary nested wrappers are not added without evidence. Canonical-store lookup
     remains mandatory. This corrects the old transport-shape assumption, preserving the
     approved behavior; it introduces no new provider scope or owner product decision.
   - Then **load the canonical store** for the re-resolved project. Append only for refs whose
     question actually exists there. Tool output and prefixes never authorise anything.
4. **Append.**
   - `paseo.agents.ref(agent.id).timeline.append({ type: "plugin", id: rowId, kind: ROW_KIND, version: ROW_VERSION, data })`,
     with `rowId = "q." + sessionId + "." + questionId` (corrected: session ids cannot contain a
     dot, so the row id is unambiguous even though question ids may; see the ID clarification
     below) and `data = { projectId, sessionId, questionId }`.
   - `version` is the registered renderer schema version (1). It is **never** a refresh
     counter.
   - A replay (the `turn_ended` folded history repeats earlier turns, a reconnect redelivers)
     re-appends the same id with identical data, which is a harmless in-place fold.
   - An in-process `appended: Set<agentId/rowId>` avoids redundant calls within a process
     lifetime, and is not required for correctness.
5. **Reconnect, epoch and cleanup.**
   - `subscription_restored` or `replacement` → run one `timeline.refetch()` scan through the
     same validation (catch-up), then continue.
   - Subscriptions are removed on `turn_ended` (after its snapshot scan), on `agent.archived` and
     `agent.closed`, on any subscription error, and on plugin cleanup. Await the unsubscribe
     `ready` per the API note.
   - A failure is logged with fingerprints only and never retried in a loop.
6. **P5.4, UI answers.** Rows are ref-only. The renderer reads the current question through the
   host query cache (corrected: `useRoadmapVersion` polls every 3000 ms while mounted; a
   revision change or a panel mutation invalidates the session queries, and `useSessionView`
   has no interval of its own; same key scheme, `client/hooks.ts`). So a UI or chat answer is reflected in existing rows
   **without** re-append and without a version change. The store stays the authority.
7. **Host gap recorded.** Subscribe and append have no ownership enforcement. Safety relies on
   self-scoping (step 1) and is documented in OVERVIEW.

**NOT READY: E6 (technical, read-only).** Confirm OpenCode and Pi exact MCP tool-call names

timelines, names and shapes only. Then add their exact entries to `TOOL_NAME_SET`. Until then,
those providers get the panel, slash command and renderer, but no automatic rows. That is a
