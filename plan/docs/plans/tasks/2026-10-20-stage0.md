### P0.3 Graph rules (`shared/graph.ts`)

All functions are pure: they never mutate inputs and return new `Session[]` (`deepClone` then
edit). They throw `DomainError` with the listed codes.

```ts
export type AnswerInput = { optionId?: string; text?: string; note?: string; quoted?: string;
                            source: "ui" | "chat"; actor: Actor; at: string };
export type GraphChange = { sessions: Session[]; staleMarked: Ref[]; visibilityChanged: Ref[] };

export function findQuestion(sessions: Session[], ref: Ref): Question;            // not_found
export function validateGraph(sessions: Session[]): void;                         // unresolved_ref | relation_cycle
export function computeVisibility(sessions: Session[]): Map<RefKey, Visibility>;
export function invalidationClosure(sessions: Session[], start: Ref): Ref[];      // downstream, excl. start, stable order
export function layoutDepth(sessions: Session[], sessionId: string): Map<string, number>;

export function applyAnswer(sessions: Session[], ref: Ref, input: AnswerInput):
  GraphChange & { rev: number; valueChanged: boolean };
export function confirmAnswer(sessions: Session[], ref: Ref,
  by: Pick<AnswerInput, "source" | "actor" | "at" | "quoted">): GraphChange & { rev: number };
export function updateDefinition(sessions: Session[], ref: Ref,
  patch: Partial<Pick<Question, "title" | "context" | "options" | "recommendedOptionId" | "allowFreeText">>,
  at: string): GraphChange & { definitionRev: number };
export type Relation =
  | { kind: "activation"; target: Ref; activation: Activation }
  | { kind: "invalidation"; target: Ref; invalidation: Invalidation };
export function addRelation(sessions: Session[], rel: Relation): GraphChange;
export function removeRelation(sessions: Session[], rel: Relation): GraphChange;
```

Rules (SPEC §6), precisely:

- **Edges.** Combined DAG edge `parent → child` for every `child.activatedBy[i].parent` and every
  `child.invalidatedBy[i].upstream`, across all sessions. `validateGraph` first checks every
  ref resolves (`unresolved_ref`, `details: { refs }`), activation `optionIds` exist on the
  parent (`unresolved_ref`), then runs a DFS with white/grey/black colouring
  (`relation_cycle`, `details: { cycle: Ref[] }`). Self-edges are cycles.
- **Visibility.** Memoised DFS over activation parents only (graph is acyclic after
  validation). A question is `active` iff for every activation `a`: parent is `active`,
  parent `validity === "valid"`, and `parent.answer?.optionId ∈ a.optionIds`. No activations ⇒
  `active`. Nothing about visibility is written into `Question`.
- **applyAnswer.** Reject when inactive (`question_inactive`); `invalid_input` unless exactly
  one of `optionId`/`text`, `optionId` exists, `text` only with `allowFreeText`. Append
  `Answer { rev: revisions.length + 1, ... }`, set `answer`, `validity = "valid"`, clear own
  `stale`. `valueChanged` = previous answer absent, or `optionId`/`text` differ. When the
  previous answer existed and value changed: for every ref in `invalidationClosure` (traversed
  through all downstream questions, whether answered, active or not) whose question has an
  `answer`, set `validity = "stale"`, `stale = { causeSessionId, causeQuestionId, causeRev:
  newRev, at }` (overwrites an older cause) and collect it in `staleMarked`. Inactive
  downstream questions are marked too (hidden validity is preserved and revealed on
  reactivation). `visibilityChanged` = refs whose computed visibility differs before/after.
  A first answer (no previous answer) marks nothing stale.
- **confirmAnswer.** Requires `validity === "stale"` (`not_stale`) and active
  (`question_inactive`). Appends a revision with the same `optionId`/`text`, clears `stale`,
  `validity = "valid"`, no propagation.
- **updateDefinition.** Validates the patched question (`invalid_input`), bumps
  `definitionRev` by 1 when any patched field differs from its current value (a no-op patch
  leaves it unchanged). If the current answer's `optionId` is no
  longer in `options`, or `allowFreeText` became false while the answer is text: mark the
  question itself stale with `cause = itself, causeRev = answer.rev`. No downstream propagation.
  Activation edges elsewhere that reference a removed option id ⇒ `unresolved_ref` (the caller
  must remove that relation first).
- **addRelation/removeRelation.** Validate both refs resolve; add is idempotent-rejecting
  (`invalid_input` on duplicate edge), then `validateGraph` on the result (cycle ⇒ throw, input
  untouched). Never marks stale (`staleMarked: []`); reports `visibilityChanged`.
  Remove of a missing edge ⇒ `not_found`.
- **layoutDepth.** For questions of `sessionId`: depth = length of the longest path from any
  root of the combined DAG (roots have depth 0; parents in other sessions count). Memoised.

### P0.4 Snapshot store (`server/fs-port.ts`, `server/ids.ts`, `server/store.ts`)

```ts
export interface StoreFs {
  mkdir(path: string): Promise<void>;                     // recursive
  writeFileDurable(path: string, data: string): Promise<void>;  // open/write/fsync/close, fails if exists ("wx")
  rename(from: string, to: string): Promise<void>;
  fsyncDir(path: string): Promise<void>;
  readFile(path: string): Promise<string>;                // ENOENT surfaces as error with code "ENOENT"
  readdir(path: string): Promise<string[]>;
  rm(path: string): Promise<void>;                        // recursive, force
  lstat(path: string): Promise<{ isDirectory(): boolean; isSymbolicLink(): boolean } | null>;
  realpath(path: string): Promise<string>;
}
export const nodeStoreFs: StoreFs;   // node:fs/promises

export type StoreReadResult =
  | { status: "missing" }
  | { status: "ok"; revision: number; changeToken: string; disabled: boolean; data: RoadmapData }
  | { status: "invalid"; revision?: number; error: { message: string; issues?: unknown } };

export interface StoreOptions { storeRoot: string; projectId: string; fs?: StoreFs;
  now?: () => Date; newId?: () => string; keepGenerations?: number /* default 2 */ }

export interface Store {
  readonly storeRoot: string;
  readonly projectId: string;
  init(): Promise<{ created: boolean; revision: number }>;
  read(): Promise<StoreReadResult>;
  version(): Promise<{ exists: boolean; revision: number | null; status: StoreReadResult["status"] }>;
  transact<T>(expectedRevision: number, fn: (draft: RoadmapData) => T):
    Promise<{ result: T; revision: number }>;
}
export function openStore(opts: StoreOptions): Store;
```

On-disk layout (SPEC §5): `.decisions/manifest.json`,
`.decisions/generations/<gen>/roadmap.json` (`RoadmapMeta`),
`.decisions/generations/<gen>/sessions/<id>.json`, `.../plans/<id>.json`. `<gen>` =
`g-${String(revision).padStart(10, "0")}-${ulid}`. `changeToken` = `sha256Hex(canonicalJson(data))`.

Behaviour:

- **Mutex.** One promise-chain lock per resolved `storeRoot` held in a module-level
  `Map<string, Promise<unknown>>`, so two `Store` objects for the same root also serialize.
- **init.** Under the lock: if `manifest.json` exists, return `{ created: false }` when the
  manifest validates and its `projectId` matches, otherwise throw `project_mismatch` /
  `store_invalid`. Else commit revision 1 with empty `meta`/sessions/plans.
- **read.** Read and validate the manifest; check `manifest.projectId === projectId`
  (`project_mismatch` thrown, not returned); reject `generation` not matching `GEN_RE` or
  resolving outside `generations/` (`invalid`). Load `roadmap.json`, every listed session and
  plan file; Zod-validate; check each file's id equals its filename; check no extra or missing
  ids; run `validateGraph(sessions)`; recompute `changeToken` and compare. Any failure ⇒
  `{ status: "invalid", error }` and **nothing is written or reset**. `ENOENT` on the manifest ⇒
  `missing`. Read always goes to disk (external edits such as `git checkout` are picked up
  without a cache; Stage 1 may add a changeToken-keyed cache).
- **transact.** Under the lock: `read()`; `missing` ⇒ `store_missing`; `invalid` ⇒
  `store_invalid` (read-only); `disabled` is still writable; `revision !== expectedRevision` ⇒
  `revision_conflict` with `details: { expected, actual }`. Call `fn(deepClone(data))`; a throw
  propagates and nothing is written. Validate the draft (schema + `validateGraph`) ⇒
  `invalid_input` on failure. Recompute `meta.sessionIds/planIds` from the draft. Commit.
- **commit (crash-safe order).** 1) `mkdir generations/<gen>/sessions` and `/plans`;
  2) `writeFileDurable` every file; 3) `fsyncDir` on the generation dir and its subdirs and on
  `generations/`; 4) `writeFileDurable(.decisions/manifest.json.tmp-<ulid>)`;
  5) `rename` tmp → `manifest.json`; 6) `fsyncDir(.decisions)`; 7) prune: remove every
  `generations/*` entry and stray `manifest.json.tmp-*` except the current and the newest
  `keepGenerations - 1` older generations by revision. Prune failures are logged-and-ignored
  (return value unaffected). A crash before step 5 leaves the old manifest authoritative; the
  orphan directory is removed by the next commit's prune.
- **ULID.** `server/ids.ts`: Crockford base32, 48-bit ms time + 80 random bits from
  `randomBytes`; monotonic within the same ms is not required.

`resolveProject` checks, in order, each failure a `DomainError`:
- `projectId` non-empty and matches `/^[A-Za-z0-9_-]{1,128}$/` (`invalid_input`);
- exactly one registered project with that id (`unknown_project`; zero or duplicates);
- `projectRootPath` is absolute and normalised (`path.isAbsolute`, `path.normalize(p) === p`,
  no trailing separator except `/` itself rejected) (`unsafe_root`);
- the registered root resolves to a directory; if its normalised realpath differs from the
  registered path, every registered-path component is inspected with `lstat` and must be a real
  directory, not a symbolic link (`unsafe_root`; a registered root that is, or lies behind, a
  symlink is refused rather than followed); `storeRoot` is the normalised realpath result
  (amended 2026-10-22, `docs/plans/2026-10-22-root-case-compatibility.md`; the original clause
  required `realpath(projectRootPath) === projectRootPath`);
- `<root>/.decisions`, if present, is a real directory, not a symlink (`unsafe_root`);
- no caching in Stage 0 (Stage 1 may cache per `projectId` with invalidation).

`projectIdForWorkspace`: exactly one workspace with that id, else `not_found`.
`openProjectStore` = `resolveProject` then `openStore({ storeRoot, projectId })`; the store then
enforces `manifest.projectId === projectId`.

### T0.2 Graph (`server/graph.test.ts`) — each bullet is one `it`

Activation and cross-session:
- `q2` inactive with no `q1` answer; inactive after `q1=a`; active after `q1=b`.
- Branch switching A→B→A→B: `q2` answered `yes` while active keeps `answer`, `revisions` and
  `validity: "valid"` through A (inactive) and shows them again on B; nothing about visibility
  is stored (`JSON` of `q2` identical before/after visibility flips other than via its own
  writes).
- Cross-session: `s2/x1` active only when `s1/q2` is active, valid and `yes`; flipping `s1/q1`
  to `a` makes `x1` inactive (inactive parent deactivates child).
- Stale parent deactivates children: make `q2` stale (via an invalidation edge from `q1` and a
  value change) ⇒ `x1` inactive; `confirmAnswer(q2)` ⇒ `x1` active again.
- `applyAnswer` on an inactive question throws `question_inactive` and returns nothing.

Invalidation:
- First answer to `q1` marks nothing stale.
- Changing `q1` a→b marks answered `q3` and transitively answered `q4` stale with
  `cause {s1,q1,rev 2}`; unanswered downstream stays `unanswered`; `staleMarked` lists exactly
  the answered refs.
- Re-answering `q1` with the same value creates rev 3, `valueChanged: false`, no stale marks.
- Invalidation reaching an inactive question is recorded: `x1` answered while active, then
  `q1` changed so `x1` becomes inactive *and* stale; switching back reveals `validity: "stale"`
  with the recorded cause (not the old `valid`).
- Activation-only edges do not propagate stale (`q2` stays `valid` when `q1` changes and `q2`
  has no invalidation edge).
- Confirm on a stale question appends a revision with the same value, clears `stale`;
  confirm on a non-stale question throws `not_stale`.
- Removing the option the current answer uses marks that question stale with itself as cause
  and bumps `definitionRev`; downstream untouched.

Graph integrity:
- `addRelation` with an unknown session or question throws `unresolved_ref`; activation with an
  unknown option id throws `unresolved_ref`.
- Pure activation cycle, pure invalidation cycle, **mixed** cycle (`q1 –act→ q2 –inv→ q1`),
  cross-session mixed cycle (`x1 –inv→ q1` when `x1` already depends on `q1`) and a self-edge
  all throw `relation_cycle`; the input `sessions` array is deep-equal to before.
- Duplicate edge add ⇒ `invalid_input`; removing a missing edge ⇒ `not_found`.
