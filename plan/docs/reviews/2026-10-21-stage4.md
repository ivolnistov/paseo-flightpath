## Implemented READY scope

Provider defaults to none and mode to dry-run. UI-only preview/apply require the latest plan's
current verified receipt and decision basis. Preview shows the entire actionable batch,
destination, mode and exact payload object; no subset selection exists. The HMAC binds project,
plan, revision/hash, receipt, settings/destination/mode, store revision, action identities and
payloads. Apply rebuilds that batch from fresh data and rejects drift. Action IDs are strict
canonical encodings; close remains rejected until O3.

Dry-run validates but creates no intent/mapping and makes no adapter call. Runtime has no live
adapter (`live: {}`); selecting live yields tracker_unavailable. The injectable fake boundary is
tested for durable pending→sent before dispatch, outcome recording and mappings, foreign-write
stops, ambiguous/time-out unknown outcomes, bounded local recording retries and interrupted
intents without blind resend. Reconcile performs no remote search or mutation.

The tracker key uses versioned JSON with32 random bytes, no-clobber publication and required
directory fsync, file0600 and directory0700. Invalid or permissive existing files fail closed
without replacement. Preview/apply/reconcile and the separate read-only tracker.list are UI
RPCs. The MCP surface remains exactly13 tools with no tracker tool.

The list closes a task-card dataflow gap: frozen Stage3 PlanGet omits tickets/intents. Its own
RPC performs one canonical project-store read, independent of approval/settings/provider, and
returns minimal ticket/intent metadata without payloads, destinations, idempotency keys, tokens,
settings or receipts. It never calls transactions, adapters, token keys or export repair.

The client includes settings, an exact-preview modal, results and persistent ticket/attention
lists. Request/opening generations protect stale preview/apply completions; Apply is guarded
during load, task captions are pinned with the preview, and settings Save uses the draft's
captured revision. Stage3 approval/task/Verify held identities are preserved. These client
claims passed independent source review and await live web acceptance.
